# Next-level ideas — grounded ideation round, 2026-07-26

> Produced by a 7-agent round: 2 miners (deferred-work registry, ISSUES/PRFAQ/ADRs/decisions; prior-art corpus of 21 tools) → 4 ideation lenses (adoption, ecosystem, capability, institution) seeded with that ground truth → 1 judge (dedupe, kill, score, rank). Scores: **impact** / **effort-fit** (5 = solo maintainer lands the first step in days) / **identity-fit** (static, no-server, open-standards).

## Ranked

### 1. Version-anchored citation: publish the note's biography and freeze a citable version anchor
*Lens: institution + capability (merged) — impact 5 · effort-fit 5 · identity-fit 5*

Give the published artifact two anchor grammars: #note-<logicalId> (concept anchor, always current — already frozen by test) and #note-<logicalId>@v3 (version anchor, immutable forever), rendered from the version chain publish already writes. A citation then resolves to the sentence the author actually cited, in 2029, after three rounds of revision — Zenodo's concept-DOI/version-DOI split, applied to a region of an image. Second beat: a Viewer history panel rendering merge lineage from spine/merge.ts's currently-unreachable lineage/ancestors.

**Why ranked here:** Highest ratio on the board, and the only idea here where the hard part is already done and shipping unread. Verified: site.ts:511-521 writes {slug}/annotations/history/{logicalId}.json + index.json into every published tree, serialize.ts:135 already mints {baseUrl}{logicalId}/v{n} ids, and static-pages.ts renders only the heads projection — so a scholar can see and link nothing that resolves to a version. Every comparator in the 21-tool corpus stores current-state rows and treats edit history as a private audit log; this is the one defensible position nobody else can occupy, and occupying it costs a string builder. The skeptic's discount lands on the tail, not the head: the published-id registry (citations.json carried through merges) is genuinely hard and is NOT in this first cut.

**0→1 first step:** Add a versionsHtml block to exhibitPageHtml in packages/render-core/src/publish/static-pages.ts: for any note with version > 1, a collapsed <details> listing prior versions with id="note-<lid>@v<n>", date, and (when available) editor, fed from the same records site.ts already hands toHistory. Snapshot-test it and assert static-pages.test.ts's existing frozen #note-<lid> grammar is untouched. Zero JS, zero new files, zero new data on the wire.

**Touches existing plans:** P-1 (docs/decisions/PROPOSALS.md) already collapsed per-note citation onto #note-<logicalId> — the @v grammar must be strictly additive or citations already in the wild break. Issue 13 (identity read-only; asClientId always yields "anonymous") means the surface degrades to what-and-when without who — ship it that way rather than blocking on Issue 13. History sidecars grow unbounded on heavily-edited notes: lazy-fetch, or the CI reader-payload budget ratchet catches you.

### 2. Pull-merge: every published exhibit is already a fetchable annotation remote
*Lens: ecosystem — impact 5 · effort-fit 4 · identity-fit 5*

Teach Studio to open a published URL through the existing HTTP read seam, run readAnnotations on {slug}/annotations, and feed the result to the same mergeLogs the zip path uses. Publishing becomes the send; pasting a URL becomes the receive. A teacher pastes thirty GitHub Pages URLs — or one URL from a student who already merged five — and the parked batch-zip intake stops being the only classroom answer.

**Why ranked here:** Inverts collaboration from push-to-an-inbox (recorded as NEVER BUILD, server-shaped) to pull-from-a-peer — git's model, and the only serverless shape that scales past two people. Every piece is verified present: openLibraryFromTree already composes new HttpFilesystem(base) with fsJsonSource, readAnnotations(annDir) takes an FsDirectory, mergeLogs and MergeReview exist, and publish writes the whole DAG. Archie is the only tool that publishes a version DAG as static files, so it can be the only tool whose published site is a mergeable remote. Docked one on effort because the Studio flow is weeks and identity is a hard blocker for the classroom story, not an adjacent nicety.

**0→1 first step:** A Node probe, no UI: scripts/probe/pull-merge.mjs publishes the Voynich seed to a temp dir (reuse the harness in scripts/perf/publishrun.mjs), serves it on a static port, constructs new HttpFilesystem(base), calls readAnnotations on {slug}/annotations, and prints per-logicalId classifyLogical(local, remote, id) against the local log. If it prints merge classifications, the whole feature is a dialog over MergeReview. One day, and decisive.

**Touches existing plans:** Classroom BATCH LOCAL zip import is PARKED (Archie-f1e2) — this is a different mechanism, not a revive of the parked item. Issue 13 identity capture is a hard dependency for attributed classroom merges. Does NOT collide with ADR-0003's rejected git-on-folder three-way merge: HTTP is transport only, Archie's DAG still does the merging, so the "line-diff-on-JSON is the wrong granularity" objection does not apply. CORS is the real edge — GH Pages sends ACAO:*, most static hosts do not; the Tauri native-http bridge is the desktop-only escape hatch.

### 3. Machine-citable by default: Zotero metadata tags + CITATION.cff in the published tree
*Lens: ecosystem + institution (merged) — impact 4 · effort-fit 5 · identity-fit 5*

Archie never runs a registrar; it emits what one needs and consumes what one returns. Emit citation_title / citation_author / citation_date / DC.* beside the existing OpenGraph block, a CITATION.cff and CSL-JSON at the tree root, and a "Cite this exhibit / cite this note" block with APA + BibTeX on the static pages. Later beat: prefill zenodo.json from the DC metadata so a deposit uploads in one motion, and stamp the returned DOI back into JSON-LD on the next publish.

**Why ranked here:** The cheapest real reach on the list, and it closes the one axis where Quire is plainly ahead. metaTags() already exists in static-pages.ts and already emits OpenGraph, Twitter, and schema.org JSON-LD from fields the merged Dublin Core pipeline threads through — six more tags makes every published exhibit one-click filable in the reference manager every DH scholar runs, with no contributed translator needed (Zotero's Embedded Metadata translator reads citation_* / DC.* off any page). A root CITATION.cff additionally earns GitHub's native "Cite this repository" button for free on a publish that is already a git repo. Impact held at 4, not 5: nobody adopts a tool because it Zotero-saves — but every scholar who meets an exhibit and cannot file it is a dropped thread, and paired with rank 1 it makes "citable notes" true rather than aspirational.

**0→1 first step:** Emit citation_* and DC.* from metaTags() in packages/render-core/src/publish/static-pages.ts, sourced from RightsFields + library metadata already in hand. Snapshot-test the tag set, then verify by saving a real published page into a real Zotero and reading back the item type and fields — six tags, one snapshot, one human check.

**Touches existing plans:** Issue 13 makes this load-bearing rather than optional: a naively generated citation says "Anonymous". Dublin Core map (Archie-c6bf, plus the open Archie-aafd) supplies the field vocabulary. Hard scope line: Archie formats and stores identifiers, never mints or resolves them — resolution is server-shaped. Zotero's item-type mapping is finicky; a confidently wrong item type is worse than none, so validate and omit rather than emit half a record.

### 4. Fixity manifest and a BagIt-shaped deposit export
*Lens: institution + capability + adoption (merged, 4-way duplicate) — impact 4 · effort-fit 4 · identity-fit 5*

Publish writes manifest-sha256.txt in BagIt RFC 8493 format over every payload file, and Studio grows a "Deposit a copy" export that wraps the tree with bag-info.txt (Payload-Oxum, Bagging-Date, Source-Organization from the Library's rights/DC metadata). The .archie.zip is already ~90% of an archival information package; checksums plus a bag structure are the missing 10%, and they make post-publish verification a property of the artifact rather than a button in a UI.

**Why ranked here:** Verified: there is no hashing anywhere in this repo — subtle.digest, createHash, and sha256 all return zero matches across packages/ and apps/. So both halves are new, and both are small. This moves "the files are yours" from a promise to a submission package a university repository's ingest workflow accepts without a human transcribing anything, and nothing in the surveyed field emits fixity or a preservation package. Impact held at 4 because it is contingent on an institution showing up, which has not happened. Effort docked to 4 for one verified hazard: incremental publish is real (site.ts:119 IncrementalScope), so a partial republish would ship a manifest that fails its own verifier unless invalidation is designed in from the first commit.

**0→1 first step:** Write the manifest in publish/site.ts as the second-to-last file — payload hashes only, BEFORE archie.json, preserving the content-first/marker-last commit ordering the data-integrity rule mandates — using crypto.subtle.digest in both browser and Node. Then scripts/verify-publish.mjs fetches a published base URL and re-hashes every listed file, exiting non-zero on mismatch. Red-green provable by truncating one tile. Gate the bag itself in CI against the reference `python -m bagit --validate`, so conformance is an external validator's verdict rather than a claim.

**Touches existing plans:** ADR-0020 rejected integrity hashing ON THE MARKER — this must be argued as agreeing with it, not reversing it: separate file, catches accidents (bitrot, truncated upload, half-synced mirror), makes no authentication claim. PRFAQ deferred automated Internet-Archive upload as "a different job" — that reasoning still holds; this is packaging only. Sits directly above the personas list's "post-publish fetch verification". Hashing a DZI-tiled tree is thousands of files: hash during the existing write pass and measure end-to-end with scripts/perf/publishrun.mjs before believing it is cheap (flow-not-primitive).

### 5. "Open in Archie" — an inbound URL grammar, then get the button onto other people's pages
*Lens: adoption — impact 5 · effort-fit 4 · identity-fit 5*

Give Studio an inbound grammar (?iiif-content= / ?manifest=) that lands a stranger in a playground exhibit built from the manifest they were already looking at, with nothing written until they commit — then get "Open in Archie" onto the viewer-chooser button rows IIIF institutions already maintain. It also inverts the planned outbound "Open in Mirador" work from a one-way trust claim into a two-way interop story.

**Why ranked here:** Verified: grep for URLSearchParams|location.search across apps/studio/src returns nothing — Studio has no front door but itself, while decodeContentState, classifyIiifDocument, and manifestToExhibit(json, url) all already exist. Every entry path today is centripetal: someone must already be at Archie. This makes every IIIF manifest on the web a potential entry point at zero marginal maintainer cost, and the verb is category-unique — Mirador, UV, Clover, and Theseus all sit on institutional viewer-chooser rows offering to READ a manifest; nobody offers to ANNOTATE it. Not ranked higher because the impact lives almost entirely in the outreach tail (PRs against institutional pages, IIIF Slack, a Community Call), which is maintainer calendar time the code cannot buy, and because CORS fails the web path on hostile hosts.

**0→1 first step:** Handle ?iiif-content= and ?manifest= on the Studio route: decode via the existing decodeContentState, run classifyIiifDocument → manifestToExhibit, land in the existing playground model so nothing is persisted until the visitor commits. Drive-test against three real institutional manifests (Yale Beinecke is already in fixtures) and measure time-from-click-to-first-annotation.

**Touches existing plans:** ADR-0008 (data-presence is the honest signal) — the param is an import intent that is consumed and discarded, never persisted mode state or a config surface. ADR-0022 already frames Content State as an additive interop layer, so this is consistent, not a reversal. The web path must degrade honestly on CORS/redirect-hostile hosts rather than showing a dead canvas; the Tauri native-http bridge covers desktop only.

### 6. Own the HTR last mile: an ALTO adapter, then the parallel-text edition
*Lens: adoption + ecosystem + capability (merged) — impact 5 · effort-fit 3 · identity-fit 5*

Do not design an adapter registry first — write one adapter and let it dictate the interface. Map ALTO TextLine polygons to WADM SvgSelector annotations with motivation: supplementing, then let that shape define the ImportSource contract Tropy, IMMARKUS, and PAGE adapters fill later. The destination is a two-pane edition where the transcription is a real text column beside the image, line-synchronized in both directions — the internal survey found every comparator does one direction only.

**Why ranked here:** eScriptorium and Transkribus emit ALTO/PAGE with line polygons and stop; nobody turns that into a readable, annotatable, publishable thing. Archie should never compete on training HTR models — being the best consumer of them is durable. It also changes what Archie MAKES: an edition, which is the artifact manuscript scholars, papyrologists, and archival transcribers are actually graded on. And an importer is the most contributable unit in this codebase (a pure function over fixtures — no canvas, no Svelte, no perf ratchet), which is the only version of scale a solo maintainer can run: PRs to merge rather than features to write. Effort held at 3 despite a days-long first step, honestly: 400-800 line annotations on one folio immediately expose the missing spatial index and the marker overlay's per-edit cost, so the cheap step produces something not yet shippable.

**0→1 first step:** packages/render-core/src/text/alto.ts: parse one real eScriptorium ALTO export's TextLine polygons into the WadmNotePlan[] shape planWadmImport already produces, with the fixture committed. Render it with the existing note list — no new mode. If 40 line annotations land in the right places on a seed folio, the interface it needed IS the registry's interface, discovered rather than designed; if coordinate mapping fights the DZI pyramid, that is a day well spent.

**Touches existing plans:** Tier-2 backlog already names "ALTO/HTR import" (docs/GOAL.md §5a) — the higher altitude is the edition mode and the contributor seam, not the import, because import alone produces an unreadable pile. Hard dependency on the R-tree/broad-narrow hit-test borrowable, not a follow-up. Depends on non-rectangular selectors surviving the W3CImageFormat adapter losslessly, which sequences it after or alongside the v1.1 ellipse/freehand work. Do not pay the registry refactor until adapter #2 exists.

### 7. The succession proof: a versioned format spec with an independent reference reader
*Lens: institution — impact 3 · effort-fit 5 · identity-fit 5*

Answer "what survives if you stop?" with an executable artifact rather than a paragraph: a versioned docs/FORMAT.md keyed to SCHEMA_VERSION, a frozen fixture corpus (one small published tree per schema version), and a dependency-free ~300-line read-tree.mjs that imports nothing from packages/ and prints every exhibit, object, note, and version — with CI asserting its output against a golden file for every fixture.

**Why ranked here:** Impact honestly capped at 3 — it adds no capability and nobody has asked for it. It ranks this high on ratio: days of work, and it is the artifact a hostile technical reviewer at a library actually reads, converting "plain files, no lock-in" from the strongest claim in the pitch into the strongest CHECKED claim. It also pays twice more: the fixture corpus is exactly what the verified-empty MIGRATIONS registry needs for its first real migration (ranks 9 and 12 both fire it), and the reader is the spec's executable definition, so the doc cannot drift silently. Nothing else in the field can make this artifact — Tropy's store is SQLite, Omeka's is MySQL.

**0→1 first step:** Freeze one deliberately tiny published tree (two objects, NOT Voynich — tile pyramids are thousands of files) at fixtures/format/v<SCHEMA_VERSION>/, write scripts/format/read-tree.mjs with zero repo imports, and assert its stdout against a golden file in CI. Write the spec doc afterward, from what the reader had to know — that is what keeps it honest.

**Touches existing plans:** Feeds the empty MIGRATIONS registry (packages/render-core/src/migrate/migrate.ts:56, verified empty) with the per-version corpus its first real migration will need. Governed by the shared-test-fixtures rule: changing a fixture to make a test pass is exactly the forbidden move. Cap the reader hard — read-only, text output, no features, delete rather than grow — or it rots into a second implementation to maintain.

### 8. Self-replicating publish: every published exhibit ships the workshop
*Lens: adoption — impact 5 · effort-fit 2 · identity-fit 5*

An opt-in publish mode that copies the built Studio into /studio/ of the published tree, booted against ../ via the existing read-only HTTP backend — so a published exhibit is not merely readable and forkable but authorable, with no canonical host and no install. GPL-3.0 makes the tool travelling with the work ideologically coherent rather than a licensing question.

**Why ranked here:** The biggest compounding move on the board and the one with the longest honest first step — which is exactly why it ranks eighth rather than first. N published exhibits become N independent installers of Archie, each carrying a worked example, and GitHub's Fork button becomes the installer. It retires the strongest curator objection ("what happens when your hosted instance goes away") by construction rather than promise. Prior art is checked out locally at ../decap-cms — a git-backed admin app shipped inside the static site it edits, at /admin/, with no backend of its own. But the copy is the easy part: the boot-from-sibling-tree path is not, the payload/opt-in decision is real, and it promotes the verified-empty MIGRATIONS registry from queued nicety to load-bearing, because a two-year-old fork must open its own data. There is no version of this whose first step is decisive in days.

**0→1 first step:** An includeStudio option on publishLibrary that copies the built Studio bundle under /studio/ and boots it pointed at ../ as its initial import source. Prove it end to end by forking the Voynich demo repo on a throwaway account, opening /studio/ on the fork's Pages URL, authoring one note, and republishing from inside the fork — no clone, no Node, no terminal. Then run node build.mjs --check to confirm eagerGzKB did not move.

**Touches existing plans:** Strictly bigger than, and would subsume, Divergence 3 (remix-from-viewer, which still routes the visitor to a hosted Studio someone must keep alive), and sits above the personas list's read-only "viewer bundled inside export zip". Divergence 2 (studio-preview) shares the boot-Studio-against-a-published-tree machinery — sequence them together. Must live entirely outside the embed's eagerGzKB ratchet. Support-surface risk with no telemetry: a forked Studio misbehaving looks like Archie misbehaving.

### 9. Overlays: publish a Reading that targets the institution's canvases, not Archie's
*Lens: ecosystem — impact 4 · effort-fit 3 · identity-fit 5*

Keep the upstream canvas IRI at import, then emit one extra static file beside the exhibit — a standalone WADM AnnotationPage whose targets are the INSTITUTION's canvas IRIs. A small citable file that Mirador or UV layers straight over the source manifest: an interpretation that stands alone against material that stays where it belongs, at zero infrastructure cost to the institution.

**Why ranked here:** Verified: sourceCanvas appears nowhere in packages/ or apps/, and iiif-import.ts reads each canvas only to extract the image body and dims — the upstream canvas IRI is discarded at :173-188. Keeping it changes what Archie produces: today the output is a site containing a copy; this makes the output an overlay on the commons, which is the only form an institution can accept back, and the only shape in which Readings — structurally absent from all 21 surveyed tools — can escape Archie and be argued about in someone else's viewer. Effort 3: a model field add plus the first real migration plus a publish branch plus a human interop gate. Only helps IIIF-imported objects, so it can never be described as universal.

**0→1 first step:** Add sourceCanvas?: string to PlannedObject/AObject, populate it in manifestToExhibit (apps/studio/src/iiif-import.ts already walks each canvas — the id is right there), and have publishLibrary emit {slug}/overlay.json with targets remapped through sourceCanvas where present and skipped where absent. Load that file into Mirador over Yale's Voynich manifest, which is already the demo corpus.

**Touches existing plans:** This is the first real model field add, so it fires the empty MIGRATIONS registry — the migration is IN scope, not adjacent (and is arguably the best argument for doing this one first). The Mirador check is a human gate the LLM cannot self-certify, and real third-party WADM interop in Mirador/UV is already an owed STOP-for-user item (docs/IMPLEMENTATION-STRATEGY.md §C). Must not imply multi-membership Readings — ADR-0007 exclusivity is locked. Upstream IRIs drift on renumbering, so record "verified against manifest fetched on <date>" rather than promising.

### 10. Rights coverage as a computed publish gate, not a metadata field
*Lens: institution — impact 3 · effort-fit 5 · identity-fit 4*

A pure rightsCoverage(library) projection that resolves inheritance and returns per-object status (explicit / inherited / absent), a typed vocabulary of the 12 rightsstatements.org URIs plus the CC set, and one line at publish time: "3 of 40 objects have no rights statement — mark Undetermined, exclude them, or publish anyway." Rights stops being a form field and becomes a workflow state the tool tracks, and the output doubles as the takedown-ready object list a collections policy requires.

**Why ranked here:** RightsFields exists at Library, Exhibit, and Object rungs (verified, model.ts:124-136) and projects cleanly to IIIF, but nothing ever asks whether it is filled in. Europeana and DPLA refuse items without a standardized rights URI, so this is literally the gate between an Archie publish and an aggregator-eligible one, and it is the difference between a tool a curator uses privately and one an institution lets face the public. Impact capped at 3 because it is a projection plus a count — it changes whether a curator CAN publish, not what Archie is. It ranks here on cost: a pure function, unit-tested, no write path, no model change.

**0→1 first step:** packages/render-core/src/model/rights-coverage.ts — a pure function over Library returning { objectId, slug, status, source }[], plus the rightsstatements.org / CC URI vocabulary as a typed constant with a dated source comment. Unit-test against a fixture with mixed inheritance, then surface as one count in Studio's Publish dialog. No write path.

**Touches existing plans:** Any write-back from this surface is governed by the metadata-rights-keyed-writebacks rule — keyed partial patches only, or it clobbers metadata. Adjacent to the open Dublin Core remainder (Archie-aafd, the excluded-dcterms read-boundary question). Nag-ware is the failure mode: publishing is the product's promise, so this is a surfaced count with one-click "publish anyway", never a block. Inheritance semantics need writing down explicitly, not inferring.

### 11. Accessibility conformance as a measured build output, not a claim
*Lens: institution — impact 3 · effort-fit 4 · identity-fit 4*

Generate a conformance report from numbers the tooling can produce: axe-core violations across the library page, the static exhibit page, and one opened object; alt-text coverage as a percentage of objects; the keyboard-reachability contract the embed and Studio hold in common; and an explicit list of what is NOT machine-checkable. Ship it as a CI ratchet first, then as an accessibility.html inside every published tree. Frame it as a measured self-assessment, never a signed VPAT attestation.

**Why ranked here:** Fits this project's stated epistemics exactly — "every better must be a number this repo's tooling can produce" — and overlay accessibility is unenumerated across the entire surveyed field, so it is a credible flag to plant rather than catch-up work. It is also a procurement gate: a university cannot adopt a tool that cannot answer the EN 301 549 / Section 508 question. Ranked eleventh, not higher, for two honest reasons: day one converts a one-day script into a real backlog, and axe-core is structurally blind to canvas-overlay semantics — precisely the surface most in question — so the report must name its blind spots or it overclaims, and an overstated conformance report is a liability rather than an asset.

**0→1 first step:** scripts/a11y/axe-report.mjs — build the viewer against the existing published fixture, drive it with the repo's existing Playwright path, run axe-core on three routes, write a JSON baseline plus ledgers/A11Y.md. Wire it as a NON-blocking CI job first so the day-one violation count is recorded rather than hidden, then ratchet: violations may not increase.

**Touches existing plans:** Sits under, not instead of, the planned a11y pass — Archie-eec7 (screen-reader walk + overlay contrast gate) and Archie-cf4a (touch design pass) remain owed and are exactly what the report's blind-spot list will name. Image-aware overlay contrast is already gated on the first institutional pilot; this measurement layer is what makes that gate legible. Alt text needs a home: carrying it as a WADM body rather than an HTML attribute is standards-correct and is a small model decision of its own.

### 12. Bilingual editions: WADM Choice bodies and language-aware reading
*Lens: capability — impact 3 · effort-fit 4 · identity-fit 5*

Teach the model, serializer, and reader the WADM Choice body so a source-language transcription and its translation are alternatives over the same region, paired with IIIF language maps on labels and metadata and a language toggle in the viewer — the field currently handles language at the label layer only.

**Why ranked here:** A genuine flag-plant — Choice is typed in the W3C spec and emitted by nobody in the corpus — and it opens a class of institution that cannot use Archie at all today: bodies with statutory bilingual obligations (Canada, Wales, Catalonia, Aotearoa NZ), Indigenous-language community archives, and any project publishing a source beside its translation. The model is already 80% shaped (W3CTextualBody carries language?, and body accepts an array — but an array means "all of these", not "alternatives"). Ranked last of the survivors purely on evidence: there is zero pull for it on any channel, and the first migration it fires is a cost paid against a hypothesis. Its saving grace is that the decisive test costs one day.

**0→1 first step:** Round-trip a Choice body through serialize/deserialize and the WADM importer, seed one bilingual note in the Voynich fixture (transcription + English translation), and open the published manifest in Mirador to confirm it renders ONE alternative rather than both stacked. That interop check is the entire risk of the idea and it costs a day.

**Touches existing plans:** Fires the empty MIGRATIONS registry — competes with rank 9 for "first real migration", so pick one deliberately rather than doing both. Must be documented as orthogonal to ADR-0007 Readings membership exclusivity before the first PR, because someone will conflate language alternatives with competing interpretations. Adjacent to but distinct from the deferred "language tags on Dublin Core metadata values" (Archie-c6bf) — that is value-level tagging, this is body-level alternatives; say so, or the deferral looks reopened.

## The four themes (what "next level" actually is)

1. The published tree already contains more than it shows. The top of this list is not new machinery — it is READERS for machinery that already runs on every publish. Verified in the repo: the full version DAG is written to {slug}/annotations/history/ and read by no published-side consumer; citationIds already mints per-version ids nothing renders; buildLinkIndex computes a library-wide note graph with test-only consumers; metaTags() emits OpenGraph but no citation metadata. Four of the top five ideas are string builders over bytes already on disk. That is why the highest-impact items here also have the shortest first steps — and it is the best available answer to "what should a solo maintainer do next."

2. Turn the artifact from an output into an interface. Publish today is terminal: bytes go out and nothing comes back. Ranks 2, 4, 5, 8, and 9 each make the published tree something read BACK — a mergeable remote (pull-merge), a submission package a repository ingests (BagIt), an entry point (inbound URL grammar), an installer of Archie itself (Studio in /studio/), an overlay on someone else's commons (canvas-targeted Readings). Bidirectionality, not more features, is what "next level" actually means here, and every one of these shapes is reachable without a server because the tree is the protocol.

3. Institutional acceptability is a set of files, not a service. Fixity manifests, CITATION.cff, rights-coverage reports, an axe baseline, a format spec with an independent reference reader — every procurement gate the P1 GLAM segment imposes can be answered by a generated file that someone ELSE's validator checks (bagit-python, axe-core, Zotero itself, a golden-file CI run). This is the only growth axis a no-server solo project can run at full strength, and the external-validator-as-CI-gate pattern makes each claim provable rather than asserted — exactly the epistemics GOAL.md already demands ("'I think it looks nicer' is inadmissible").

4. Version history is the moat, and it is currently invisible. Append-only plus the version-parent DAG is the one thing structurally absent from all 21 comparators, and today it is an implementation detail: written on every publish, rendered nowhere, cited by nothing, merged by nobody over the wire. Ranks 1, 2, and 9 all cash it in — as a frozen citation anchor, as the thing that makes a peer's published site mergeable, as an interpretation layerable over institutional material. Everything else on this list is a good idea some other tool could also have; this is the only one that is Archie's alone.

## Anti-ideas — tempting moves to explicitly not make

- **Make <archie-viewer> a general IIIF manifest viewer (src="…manifest.json")** — Tempting because the src sniff seam already exists in load.ts and the element is small, and it reads as free reach into every Canopy/Quire/Wax/CollectionBuilder page. But it enters a market held by Universal Viewer and Clover, both of which have teams, and buys nothing an Archie publish does not already buy. The embed's public surface is deliberately FROZEN at three attributes with a pinned @vN tag — a forever-compatible posture that an open-ended manifest-fidelity tail destroys. The eager-closure rule exists precisely because this class of addition once silently leaked 225KB into the page-load path (257.9KB gz instead of 32.7KB) and shipped. "Read-only, one manifest, no collection browsing" sounds bounded and has never stayed bounded in any viewer project.

- **Ship in-browser speech-to-text (Whisper / transformers.js) for oral history and AV** — Genuinely appealing — no service operated, av/transcript.ts already does the VTT→timed-notes back half, and Hyperaudio Lite is checked out next door as the transcript-as-navigation donor. It is still floor two on an unbuilt floor one: the AV READING surface is itself an open UX-map child (Archie-7b86, V49/V50/V53/V29), the seed corpus has no local AV at all (Archie-b135), and the AV player and Studio AV hand-annotation human gates are still owed. Transcripts would land with nowhere good to read them. It also wants 'wasm-unsafe-eval' in the CSP, and this repo's own recorded history is that CSP changes here fail SILENTLY (both worker paths degrade with the app looking entirely healthy). Build the reading surface, then revisit.

- **Automate the deposit — upload to Zenodo or the Internet Archive on the user's behalf** — The natural-feeling next step after emitting a bag, and the exact line where packaging becomes a service integration: credentials to custody, rate limits to handle, an outage surface to own, and a failure mode where a user believes their work is deposited and it is not. PRFAQ already deferred IA upload as "a different job with different guarantees" and that reasoning is unchanged. Archie formats the package and stores the DOI the human pastes back; it never mints, resolves, or transmits. Holding that line is what keeps the whole deposit story free to maintain — and it is the same line that keeps ranks 3 and 4 identity-safe.

- **Build mirror failover — copies.json plus a client that tries alternate base URLs** — Reads as LOCKSS doctrine in the only shape a no-server product can take, and the generation-skew analysis behind it is sharp. But there are no mirrors because there are no users, so it solves a problem nobody has while introducing one that matters: blending files from two mirrors at different generations is precisely the silent-wrong-data class that the data-integrity rules make a growth-GATING finding, and a failover that swallows a fetch error converts an outage into permanent-looking data loss — the exact inversion of the intent. It also skates hard against ADR-0009's refused registry; the boundary (N copies of ONE library, never a directory of many) is one refactor from being lost.

- **Ship a CSV / spreadsheet round-trip as the "no lock-in" proof** — Export is easy, IMMARKUS already ships Excel export, and a spreadsheet is the escape hatch you instinctively want to hand a skeptic. But a flat table can only ever be the heads projection — it cannot express the version DAG, which is the one thing Archie has that nobody else does, so the artifact offered as proof of openness quietly projects away the differentiator. Worse, the round-trip half is a data-loss path by construction (edits silently become new revisions, deletions are inexpressible), and a data-loss finding gates growth here by rule. The honest proof of no-lock-in is the independent reference reader at rank 7: ~300 lines, zero repo imports, golden-filed in CI, and it reads everything including the history.
