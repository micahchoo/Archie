The cheat sheet for lesson 3. Prints on one page.

Dev ports

PortProcessConfig
5173Front door — path-routing proxy. The only URL you type. / 302s to /studio/.scripts/dev-proxy.mjs
5174Studio — Vite SPA. base: "/studio/", strictPort.apps/studio/vite.config.ts
4321Viewer — Astro. strictPort. Booted with SITE_BASE=/viewer/.apps/viewer/astro.config.mjs
5198Studio e2e — own port so a running pnpm dev never collides. Override STUDIO_E2E_PORT for concurrent runs. apps/studio/e2e/playwright.config.ts

Commands

pnpm dev                  # all three: scripts/dev.sh
                          #   → http://localhost:5173/studio/
                          #   → http://localhost:5173/viewer/

pnpm build:gh-pages       # → gh-pages-dist/{index.html, studio/, viewer/}
pnpm --filter @archie/studio e2e --config e2e/playwright.config.ts

The routing rule

url.startsWith("/studio") ? :5174 (Vite) : :4321 (Astro)

Asymmetric on purpose. Vite namespaces all its dev URLs under base, so one prefix catches its internals. Astro's internals are root-relative and need the catch-all.

Rules with teeth

RuleWhy
strictPort: trueFront-door targets are hardcoded. A silent port bump → 502 on a page that looks fine, with two healthy servers running. Fail at boot instead.
Bind 127.0.0.1Proxy forwards Vite's /@fs unrewritten — a wildcard bind puts your filesystem on the LAN.
Literal IP, not "localhost"listen() with a hostname goes through dns.lookup; the bound interface would depend on the resolver.
One origin sourcearchie.config.json → build script, Studio share links, viewer og/sitemap. Build aborts if it doesn't contain the repo name.

Symptom → cause

You seeIt's probably
502 from the front doorThat dev server isn't up (or bumped its port). The proxy names the unreachable target in the error body — read it.
Browser 404s but curl worksSomething is routing HTML navigations before its proxy middleware. This is why the standalone proxy exists; don't re-solve it with vite.server.proxy.
Vite died on bootstrictPort doing its job — a stale pnpm dev holds :5174. Kill it and rerun.
Deployed page, every asset 404sWrong --base / SITE_BASE. A static host can't rewrite; paths are baked at build time.
Viewer's exhibit vanished after another agent ran testsNot a port problem — the shared Vite dep cache. Restart Astro, don't hard-reload. See .claude/rules/viewer-optimizedeps-bare-includes.md.

What ships

gh-pages-dist/
├── index.html     hand-written landing page (in build-gh-pages.sh)
├── studio/        Vite build, --base=/Archie/studio/
└── viewer/        Astro build, SITE_BASE=/Archie/viewer/

No process. No port. A published library is a third artefact entirely — the folder Studio's publish step writes, or one .archie.zip, servable from anywhere or nowhere.
