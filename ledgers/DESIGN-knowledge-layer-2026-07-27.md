# DESIGN v2 — Archie knowledge layer, query-first (2026-07-27)

Supersedes v1 (same file, earlier today). v1 mapped Karpathy's llm-wiki onto Archie's
stores structurally (raw/wiki/schema). v2 inverts the derivation: **start from the
general queries agents actually have, assign every store exactly one role in answering
exactly one query class, retire or merge everything left over.** Same principle that
chose the hub set, applied to the whole design.

## 1. The six general queries — everything below is derived from this table

| # | the query | mechanism | how it's answered |
| --- | --- | --- | --- |
| Q1 | *what must I know, given what I'm touching?* | **PUSH** | scope-injection delivers rules + hubs unasked on file match |
| Q2 | *what's the current state of \<territory\>?* | **PULL** | read one hub (10 question-named hubs) |
| Q3 | *how do I prove \<claim\>?* | **GATE MAP** | `hubs/verification.md`'s claim→gate table |
| Q4 | *where is \<specific thing\>?* | **SEARCH** | fff / ctx FTS5 / `sd search` / `git log -S` |
| Q5 | *what happened, when, and why?* | **HISTORY** | follow a hub pointer into the raw layer (ticket ↔ sha keyed) |
| Q6 | *can I trust the knowledge itself?* | **LINT** | `scripts/doclint.mjs`, deterministic, in CI |

Design invariant: **every store is reachable by exactly one of PUSH / PULL / SEARCH /
POINTED-AT, and doclint proves total coverage.** A store reachable by none is dead
weight; a query answerable by none is a design gap. Both are mechanical checks.

### Serving Q6 (lint)

`scripts/doclint.mjs` — deterministic, exit-coded, wired into `checks.yml`. NOT /tend's
job. Checks: dangling `[[links]]` (with intentional-whitelist) · dead rule/hub scopes ·
stale hubs (`git log -1 -- <scope>` newer than `updated:`) · INDEX drift (regenerate,
diff) · TRACKERS.md referential integrity · untracked doc dirs · declared-mirror
divergence · ledger date-naming · rule-accretion count · scope-coverage totality.
Red-greened at birth against today's standing findings (dead scopes, `.agents/` mirror,
untracked `.teach/`, worktree ledger drift) — if it can't flag those, it doesn't work.

### Retired / deduped

`.agents/skills/` (byte-identical mirror of `.claude/skills/` — delete or symlink) ·
`docs/architecture/` (tool-derived tree; regenerate on demand or archive) · shadow
`HANDOFF.md`/`CONTEXT.md` inside `.scratch/` (root ones are canonical) · the three
`archie-loop-*/` output generations (keep newest, README saying so, delete the rest).

Untouched: memory dir (user-scope, harness-owned) · `.teach/` (own vault — but gets
tracked) · HANDOFF.md at root (session bus; already has a skill).

## 3. Write paths — who writes knowledge, when, enforced how

| moment | writes | enforcement |
| --- | --- | --- |
| ticket close / slice done | one hub line: `Archie-xxxx / <sha> → verdict` | **deterministic**: doclint stale-hub check goes red when commits touch a hub's scope and the hub didn't move |
| a failure was paid for | a rule (or a correction to one) | judgment; review-flagged, as today |
| citation verified or killed | line on `hubs/prior-art/<lib>.md` | convention + doclint link-integrity |
| exploration answered a question | EXPLORE-ledger (dated, immutable) + verdict line lifted into hub | stale-hub check covers the hub half |
| session end | HANDOFF.md | existing handoff skill |
| doclint finding | a seeds ticket | the CI gate itself |
| semantic contradiction (the residue) | quarterly / milestone one-shot agent pass over doclint-flagged neighborhoods → seeds tickets | bounded, on-demand; never /tend, never a loop |

## 3b. Editorial rules — how information is added and removed
(source: `~/.claude/skills/writing-great-skills` — its vocabulary, applied to the wiki)

The wiki's tiers ARE an information hierarchy, and placement is a rung decision:

| rung | wiki tier | cost model | admission bar |
| --- | --- | --- | --- |
| 1 | scope-PUSHED rule/hub | **context load** — paid by every task matching the scope | only what EVERY task in scope needs; earns the hardest pruning |
| 2 | hub body (pulled) | one file read | verdicts + pointers; what a lead needs to brief |
| 3 | raw layer behind a pointer | loaded only when the pointer fires | everything else — evidence, history, full reasoning |

- **Adding = choosing a rung, not writing prose.** New fact → default rung 3 (it's
  already there: the ticket, the ledger). It climbs to rung 2 only when a dispatch
  would need it, rung 1 only when every in-scope task would. "Push too little down and
  the top bloats" is the hub-bloat failure mode; doclint's stale-hub check can't catch
  bloat, so rung discipline is the schema's job.
- **Pointer wording decides reach.** A context pointer's wording, not its target,
  determines whether an agent follows it. Hub lines therefore carry the *stakes*, not
  just the link: `silent fallback — only witness is bakeFallbackCount(); see PERF-…`,
  never bare `see ticket`.
- **Single source of truth.** One meaning, one place — hubs point, never duplicate;
  the standing-ledger migration and the `.agents/` mirror deletion are this rule
  enforced retroactively. A meaning found in two maintained places is a doclint-able
  smell once mirrors are declared.
- **Removal is sentence-level no-op hunting.** The rewrite-after-3-corrections
  meta-rule (§2) names WHEN a rule gets rewritten; writing-great-skills names HOW:
  test each sentence for relevance and no-op in isolation, delete whole sentences,
  keep the measured evidence and the falsifiable claims, cut the narrative connective
  tissue. Corrections accrete history; a rewrite re-earns every line.
- **Checkable completion criteria on write paths.** "Update the hub" is vague;
  "every hub whose scope this diff touches carries a line for this ticket/sha" is
  checkable — and is exactly what doclint's stale-hub predicate asserts. Every §3
  write path keeps its criterion in that form.

## 4. Karpathy mapping (unchanged from v1, one line)

raw sources = Q5 layer · wiki = Q1+Q2 layers (rules + hubs) · schema = CLAUDE.md +
this doc · index.md = generated INDEX + scope-push · log.md = git + dated ledger names ·
qmd = fff/ctx · his summaries = our pointers (the deliberate inversion: a summary rots
silently, a `ticket/sha` pointer fails loudly under doclint).

## 5. Rollout — maximal, dependency-ordered, each step gated

0. **Custody**: track `.scratch/Prior Art/`, `.teach/`, this doc; kill `.agents/`
   mirror; reconcile 14 worktrees' ledger drift; root CANON pointer.
   *Gate: `git status` clean of doc-bearing untracked dirs.*
1. **doclint.mjs** + CI wiring. *Gate: red-green against the standing findings.*
2. **Ten hubs + INDEX generation + hub scope-push.** *Gate: next real dispatch brief is
   "read hub X" + territory + recon numbers, and the worker asks fewer context questions.*
3. **Schema digest into CLAUDE.md** (hub format, closure line, `ticket/sha` form,
   brief template's mandatory `hub:` line).
4. **prior-art/ seeded** from already-verified citations only (PRIORART-* ledgers,
   citation-discipline rule, ADRs). No batch summarization of anything, ever.
5. **TRACKERS.md generated** + ISSUES.md frozen + standing-ledger migration.
6. **Residue pass** (the only agent-judgment lint), first run after one month of
   doclint green.

Stop at any failed gate. Steps 0–1 are worth doing even if nothing else ships: they
protect and verify what already exists.
