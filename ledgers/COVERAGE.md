### Row 1 resolution — pursued

A second research pass against **live GitHub reference implementations** (not just local clones)
found the exact spec citation and confirmed neither reference tool actually handles this either:

- **IIIF Presentation 3.0 §5.3** (https://iiif.io/api/presentation/3.0/#53-canvas): *"A Canvas must
  have a rectangular aspect ratio (described with the `height` and `width` properties) and/or a
  duration."* A Canvas painting only an Image (no AV, no `duration`) that lacks both dimensions
  violates this outright.
- `iiif-prezi3` (Python reference tool)'s `add_image()` helper doesn't call its own `set_hwd()`
  dimension-co-requirement check — same hole. `@iiif/presentation-3-types`' `Canvas` type leaves
  `height`/`width` `Partial` with no compiler enforcement either. **No prior art to lean on** —
  this fix goes beyond what either reference implementation does.

Fix (this session, not yet committed):
- `iiif/manifest.ts`: added `findCanvasesMissingDimensions(manifest)` — a pure, tested function
  (`manifest.test.ts`, 3 new tests) that scans a built Manifest for Image-body Canvases with no
  width/height, citing §5.3 in its doc comment.
- `publish/site.ts`: new `IncompleteCanvas` type + `PublishResult.incompleteCanvases`, populated via
  `findCanvasesMissingDimensions` right after each exhibit's `toManifest` call — mirrors the existing
  `brokenLinks` sink pattern exactly (same shape: collected per-exhibit, returned from
  `publishLibrary`/`libraryToZipFs`/`libraryToZip`). New end-to-end test in `site.test.ts`.
- Studio wiring (`publish-flows.svelte.ts`, `Publish.svelte`, `App.svelte`): surfaced through the
  GitHub-publish dialog's existing advisory-block pattern (same UI slot `brokenLinks` already uses)
  plus a `console.warn` on the zip-download path, matching `brokenLinks`' precedent exactly — no new
  UI pattern invented.
- Deliberately did NOT tighten `IIIFCanvas.width`/`height` to a discriminated-union required type —
  that would ripple through every canvas constructor in `manifest.ts`/`presentation.ts` for a
  compile-time guarantee neither reference implementation provides either; a post-hoc, surfaced
  runtime check matches this repo's existing style (e.g. `asTileSourceDescriptor` in manifest.ts)
  and Issue 4's "surfaced or reported" convention rather than a type-system redesign.

Full render-core suite after this fix: **69 files / 699 tests** (3 in `manifest.test.ts` + 1 in
`site.test.ts` new), typecheck clean. Studio: **148/148** tests, typecheck clean.
